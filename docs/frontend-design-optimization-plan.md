# 前端设计语言优化路线图

> 基于 `docs/frontend-design-guidelines.md` 制定。当前目标是收敛设计系统、减少视觉漂移，不进行整页重写、不改变后台 API、配置 schema、归档数据或推送语义。
>
> 状态：首轮实施完成（2026-09-21）。后续高风险/高成本的组件抽取与真实设备矩阵仍按本文件的边界单独推进。

## 1. 当前判断

当前前端已经具备稳定的视觉基线：共享主题 token、浅色/深色模式、统一导航、卡片/表单/弹窗体系、三坂来源色和桌面/移动端断点均已存在。管理端视觉一致性阶段也已经完成并部署。

当前主要问题属于“设计系统没有完全收口”，而不是需要重新设计：

1. `theme.css`、`archive.css` 和 `index.html` 内联样式仍有重复职责；
2. 页面中存在少量硬编码颜色、间距、圆角和阴影，主题切换后可能产生局部漂移；
3. 共享组件命名和页面专用组件之间仍有边界重叠；
4. 焦点、禁用、错误、加载和 reduced-motion 状态还没有形成全站契约；
5. 视觉回归覆盖管理端较好，但归档页长列表、灯箱和真实移动浏览器的行为验证仍可加强。

结论：不需要大规模重写。优先做低风险的 token 和契约收敛，再做组件抽取和可访问性补齐。

## 2. 目标与非目标

### 目标

- 让新增页面默认复用同一套颜色、间距、圆角、阴影和状态语义；
- 让浅色/深色、三坂来源色和状态色在所有页面表现一致；
- 降低内联样式、重复覆盖和高优先级选择器造成的维护成本；
- 保证长列表、媒体灯箱、sticky 侧栏和移动端滚动稳定；
- 将视觉质量纳入自动化契约和回归测试。

### 非目标

- 不重写 `index.html` 或 `archive.js`；
- 不更换前端框架，不引入大型 UI 组件库；
- 不修改后端 API、配置字段、权限模型、归档数据库和推送逻辑；
- 不为了视觉统一删除现有功能或降低信息密度；
- 不在没有视觉回归和用户确认的情况下更换整体主题色。

## 3. 优先级与实施批次

### P0：规范落地与防漂移门禁

**目标**：让后续 agent 有明确规则，阻止新的样式债务继续增加。

工作项：

- 将 `frontend-design-guidelines.md` 作为前端任务必读规范；
- 增加静态契约检查：禁止目标模块新增布局型内联样式、检查资源版本和 HTML 结束标签；
- 梳理当前硬编码颜色、`!important` 和重复 token，区分“必须保留的媒体/第三方例外”和待迁移项；
- 在 PR/提交说明中要求注明主题、断点、缓存版本和回滚点。

验收：新增前端变更若违反规则，契约测试能给出具体文件和原因；现有页面行为不变。

### P1：Token 收口

**目标**：把颜色、间距、字号、圆角、阴影、z-index 和动效时长变成可复用语义。

工作项：

- 补充 `--space-*`、`--text-*`、`--radius-*`、`--z-*` 和状态/遮罩 token；
- 合并重复的深色主题定义，明确 `data-theme` 与系统主题的优先级；
- 将管理端和归档页仍在使用的硬编码颜色迁移到语义变量；
- 为樱坂浅色/深色选中态建立单独对比度契约，避免近白文字消失；
- 保留三坂品牌色，但禁止用品牌色覆盖全局按钮和导航。

验收：主题切换无明显色块跳变；关键文本和选中态满足对比度要求；静态扫描显示新增硬编码颜色为零或有登记例外。

### P1：共享组件收口

**目标**：减少页面各自实现的按钮、输入框、徽章、模块、弹窗和操作栏。

工作项：

- 将 `admin-*` 与归档页对应组件的共同部分提取到共享 CSS；
- 保留页面差异作为 modifier，而不是复制整套规则；
- 统一按钮三种语义、表单焦点、状态徽章、空状态和加载状态；
- 为弹窗建立统一的标题、正文、操作栏、焦点陷阱和关闭语义。

验收：同一语义组件在管理端和归档端的边框、圆角、状态和键盘行为一致；不改变现有 ID 和事件入口。

### P2：滚动、媒体与响应式稳定性

**目标**：解决长列表和真实设备上最容易产生“看起来怪”的问题。

工作项：

- 统一顶部导航、sticky 侧栏和日期跳转的安全区参数；
- 为消息时间线、博客长图、相册瀑布流提供稳定的媒体占位尺寸；
- 验证灯箱背景点击、加载未完成时的底层点击隔离和新标签页跳转；
- 在手机 Chrome、Safari/系统 WebView 和桌面 Chrome 分别检查触控、滚动和复制降级；
- 明确减少动效模式，关闭滚动绑定装饰和持续动画。

验收：1440、768、390 视口无横向溢出；相册连续下滑不出现背景跳动或内容错位；灯箱不会误触底层媒体。

### P2：可访问性与状态反馈

**目标**：让视觉统一同时成为行为统一。

工作项：

- 为所有弹窗补齐标题、描述、关闭名称和焦点回归；
- 统一 `:focus-visible`、键盘导航、Esc、禁用、加载和错误反馈；
- 检查颜色对比度、触控尺寸和屏幕阅读器可见文本；
- 动态状态使用文字/图标补充颜色，复制、保存、刷新和异步请求都显示结果；
- 对异步回包增加过期请求保护，避免旧操作覆盖新页面状态。

验收：键盘可完成主要任务；失败状态不依赖控制台；`prefers-reduced-motion` 下没有关键动画阻塞操作。

### P3：性能与资产治理

**目标**：在不牺牲视觉的情况下减少首屏和长期浏览成本。

工作项：

- 审查 CSS 覆盖链和未使用规则，避免继续扩大单页 CSS；
- 统一静态资源版本策略，确保行为变更和视觉变更都能可靠失效缓存；
- 优先使用缩略图、懒加载和 `aspect-ratio`，避免大图改变布局；
- 对灯箱和媒体预览进行内存回收检查；
- 保持页面不引入大型运行时依赖。

验收：首屏无明显白屏或布局跳变；长时间浏览相册/博客不会持续增加无界 DOM、事件监听或媒体内存。

## 4. 推荐提交边界

为方便回滚，不建议把所有视觉整理压成一个大提交：

1. `docs(ui): establish frontend design guidelines`：规范、agent 入口和静态契约说明；
2. `refactor(ui): consolidate theme tokens`：只改 token 和少量引用，不改页面结构；
3. `refactor(ui): unify shared controls`：按钮、输入、徽章、弹窗和模块组件；
4. `fix(ui): stabilize responsive archive interactions`：sticky、灯箱、媒体占位和移动端行为；
5. `test(ui): expand visual and accessibility contracts`：契约、视觉矩阵和浏览器回归。

每个提交都应独立通过相关测试，部署时使用不可变镜像标签；不要把配置、`.env`、数据库或视觉基线之外的临时图片混入提交。

## 5. 测试与验收矩阵

### 静态门禁

```text
pytest -q
ruff check .
python -m compileall -q src tests
node --check src/webui_static/archive.js
git diff --check
```

### 浏览器矩阵

| 页面/场景 | 浅色桌面 | 深色桌面 | 平板 | 手机 | 重点 |
| --- | --- | --- | --- | --- | --- |
| 管理端 | ✓ | ✓ | ✓ | ✓ | 表单、表格、弹窗、保存反馈 |
| 消息归档 | ✓ | ✓ | ✓ | ✓ | 时间线、复制、搜索、日期跳转 |
| 博客归档 | ✓ | ✓ | ✓ | ✓ | 长图、作者筛选、sticky 日历 |
| 相册/灯箱 | ✓ | ✓ | ✓ | ✓ | 媒体加载、背景点击、返回上下文 |
| 登录/错误页 | ✓ | ✓ | ✓ | ✓ | 对比度、错误提示、无横向溢出 |

视觉回归应固定字体、动画和测试数据；真实设备验证不能完全由截图替代。

## 6. 回滚与发布边界

- 纯视觉变更应能通过回滚静态资源提交恢复，不触碰 `config/`、`.env`、`data/` 和数据库。
- 发布前确认静态资源查询版本已递增，避免旧缓存掩盖结果。
- 任何同时涉及后端 API、配置 schema 或数据迁移的改动必须另立计划，不得借 UI 优化顺手合并。
- NAS 发布必须在本地质量门禁和远端 CI 通过后进行，并核验镜像 SHA、容器健康状态和静态资源指纹。

## 7. 首轮实施建议

如果后续要继续优化，建议从以下低风险顺序开始：

1. 先落地 P0 的契约门禁和 token 清单；
2. 只迁移最容易造成主题不一致的硬编码颜色和焦点状态；
3. 选择按钮/输入/状态徽章作为第一批共享组件，不碰页面结构；
4. 之后再处理 sticky、灯箱和真实移动浏览器行为；
5. 每一批由用户确认视觉效果后再进入下一批。

## 8. 首轮实施记录

本轮在不改变页面结构、HTML ID、后台 API、配置 schema 和归档/推送语义的前提下，已落地以下基础能力：

- **P0 契约门禁**：新增 `tests/test_frontend_design_contracts.py`，检查共享 token、四个前端页面的唯一 HTML 结束标签、静态资源版本同步、灯箱/滚动稳定性和樱坂选中态对比度。
- **P1 token 收口**：在 `theme.css` 增加间距、字号、圆角、焦点、遮罩、层级、动效和 hover 语义 token；顶部导航、下拉、对话框遮罩和归档关键层级开始引用 token。主题资源版本统一递增。
- **P1/P2 交互基础**：全站补充统一 `:focus-visible` 与禁用态基础规则，`prefers-reduced-motion` 下关闭关键动画和 smooth scroll；归档自定义确认/输入弹窗支持 Esc、初始焦点和关闭后焦点回归，并补齐缺失的 dialog ARIA 标识。
- **P2 归档稳定性**：sticky 日历和日期跳转使用同一套安全区 token；瀑布流图片无尺寸元数据时保留稳定占位比例；灯箱关闭逻辑只接受真实图片或背景目标，避免 stage 事件误穿透到底层相册卡片。
- **P3 资源治理**：归档 CSS/JS、共享主题的查询版本已同步更新；未引入运行时依赖，继续使用懒加载、`aspect-ratio` 和现有媒体观察器。

以下项目刻意保留为后续独立批次，不在首轮通过大范围重写隐式完成：

1. 管理端与归档端全部按钮/输入/弹窗 CSS 的完整抽取；
2. 历史硬编码颜色和布局内联样式的逐项迁移（现有动态显示逻辑需逐项回归）；
3. 手机 Chrome、Safari/WebView 和桌面 Chrome 的真实设备交互矩阵与视觉基线扩展；
4. CSS 覆盖链和未使用规则的量化清理。

这些项目仍须遵循“一个视觉维度、一个可回滚提交”的边界，不能借普通 UI 调整改变 API、配置或数据行为。
